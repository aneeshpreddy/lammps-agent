**Why each check matters.** The oracle shows that a correct file is always scored a success (no false failures from the harness, configurations or references). The mock baseline shows that the baseline's output schema can express every dev task and that its conversion to builder specs is faithful, so a baseline failure is the model's, not the glue's. The file corrupter shows that invalid files are not scored as successes; the spec corrupter shows that valid files of the wrong system are not either (TC.2 does its job). The three agent checks show that the loop validates every attempt, turns a caught defect into feedback that leads to a fix and a scored success, and stops a model that repeats its failure (escalation) — all with scripted models, so they check the loop, not a model. The last two show the known limitation of C (a valid but wrong build is accepted, and only TC.2 afterwards sees it) and that variant E's request check closes it when the request states the field (here the mock's extraction is perfect, so this checks the plumbing, not the extraction).
